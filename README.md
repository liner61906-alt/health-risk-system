# 智慧健康日誌與風險評估系統

## 一、專案說明

本專案選擇期末挑戰任務中的題目 A：智慧健康日誌與風險評估系統。

系統讓使用者輸入每日健康資料，包含睡眠時數、步數與心情分數。後端會使用決策樹分類邏輯，依序判斷「睡眠 → 步數 → 心情」，最後分類出目前健康風險等級：低風險、中風險或高風險。

---

## 二、系統功能

本系統包含以下功能：

1. 新增每日健康日誌  
   - 日期
   - 睡眠時數
   - 步數
   - 心情分數

2. 自動風險分類  
   - 使用決策樹分類邏輯
   - 依序判斷睡眠、步數、心情
   - 輸出低風險、中風險、高風險

3. 歷史紀錄列表  
   - 顯示所有健康日誌
   - 包含日期、睡眠時數、步數、心情分數、風險等級

4. 最新風險等級顯示  
   - 顯示最新一筆健康資料的風險分類結果
   - 以顏色徽章呈現低風險、中風險、高風險

5. 刪除資料  
   - 可刪除指定健康日誌紀錄

## 四、資料表設計

資料表名稱：health_logs

| 欄位名稱 | 型態 | 說明 |
|---|---|---|
| id | INTEGER | 主鍵，自動遞增 |
| log_date | TEXT | 紀錄日期 |
| sleep_hours | REAL | 睡眠時數 |
| steps | INTEGER | 當日步數 |
| mood_score | INTEGER | 心情分數，1～10 分 |
| risk_level | TEXT | 決策樹分類後的風險等級 |

---

## 五、決策樹分類邏輯

本專案使用多層分支的決策樹，不是單一 if 判斷。

決策流程如下：

1. 先判斷睡眠時數
2. 再判斷步數
3. 最後判斷心情分數
4. 輸出風險等級

分類邏輯：

- 如果睡眠少於 6 小時，且步數少於 4000，且心情分數小於等於 4，判定為高風險。
- 如果睡眠充足，步數大於等於 6000，且心情分數大於等於 6，判定為低風險。
- 其他中間情況判定為中風險。

## 六、API 設計

| 方法 | 路徑 | 功能 |
|---|---|---|
| GET | /health-logs | 取得所有健康日誌 |
| POST | /health-logs | 新增一筆健康日誌 |
| GET | /health-logs/risk | 取得最新一筆風險等級 |
| DELETE | /health-logs/:id | 刪除指定健康日誌 |

---

## 七、資料流說明

本系統的資料流如下：

Frontend → API → Database

使用者在前端輸入健康資料後，前端會呼叫 `POST /health-logs` API。後端收到資料後，會先使用決策樹計算 `risk_level`，再將資料寫入 SQLite 資料庫。

前端之後會呼叫 `GET /health-logs` 重新取得歷史紀錄，並呼叫 `GET /health-logs/risk` 顯示最新風險等級。
